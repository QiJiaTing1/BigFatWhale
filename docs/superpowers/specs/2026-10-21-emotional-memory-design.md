# 情感记忆设计（Emotional Memory）

日期：2026-10-21
状态：设计已对齐，待写实现计划

## 背景与目标

现有记忆分两层：

- **短期上下文**：最近几条消息，带时间戳（`plugins/ai_group.py` 的 `_history`）
- **长期记忆**：事实档案，谁喜欢什么、稳定偏好（`plugins/long_memory.py`）

缺一层「情绪/关系」：机器人记不住群友最近心情如何、谁和谁关系怎么样，
所以关心和共情显得假。本设计补上这一层。

经调研 2026 年 Agent 记忆框架（Zep / Mem0 / Letta / Generative Agents 等），结论：

- 「遗忘（forgetting）」是最被忽视却最关键的维度——能打 95% 召回却仍吐过期事实的系统很常见。
- 情绪记忆尤其需要衰减（VividEmbed 指数衰减、cogmem 半衰期随唤醒度变长、MemoryBank 艾宾浩斯曲线）。
- 情绪短期、关系长期，正好匹配真人直觉，也是本设计的取舍。

## 范围

- **记**：情绪/心情（谁最近开心、难过、emo、压力大）+ 人际关系（谁和谁熟/不对付、谁对鲸鱼娘什么态度）
- **不记**：情感事件（生日/约定/离别）——本次不做，YAGNI
- **主人单独存档**：主人的私聊有独立情感档案，只在私聊用，不注入群聊（群聊暂不需要）

## 方案：独立情感档案（方案 B）

事实档案一行不动；另建独立情感档案，情绪指数衰减、关系长期。

选它的理由：情绪会过期、事实不会过期，是两类东西，分开最干净，避免去重/字数上限互相污染；
衰减用几行指数公式即可落地，不引入 embedding（方案 C 过度设计）。

## 数据模型

新增 `memory/情感记忆.json`，顶层结构 `{ "<key>": [条目] }`，`key` = 群号或私聊 `user_id`。

每条字段：

| 字段 | 说明 |
|---|---|
| `id` | 自增，供 UPDATE/DELETE 定位 |
| `subject` | 谁；情绪=单个人，关系="小明↔小红" |
| `kind` | `emotion`（情绪）或 `relation`（关系） |
| `fact` | 一句话，≤30 字，如"最近失恋心情低落" |
| `intensity` | 情绪强度 0~1（只有情绪有；关系为 null） |
| `date` | 完整日期 `YYYY-MM-DD`，算衰减用 |

## 接口（对 key 无感知）

沿用现有 per-key 设计，`key` 为不透明 id（群号 or 私聊 user_id），隔离是自带的：

- `add_pending(key, name, text)` — 消息进「待合并」缓冲
- `consolidate_emotion(key)` — 情感整理合并（LLM）
- `emotion_text(key)` — 读该 key 的情感档案，产出注入文本（读取时顺带衰减过滤）
- `stats(key)` — 统计

主人的私聊 `key = 主人QQ`，天然与所有群隔离 → **主人单独存档自动成立**。
以后若想让主人情感进群聊，只改调用点，不动存储。

## 触发 & 合并

复用现有「攒够 `MEM_CONSOLIDATE_EVERY` 条就合并」机制。触发时：

- 事实合并照旧（现有 `consolidate` 不动）
- 另跑一次「情感整理」合并：独立 prompt，让模型从新消息里挑出「谁情绪怎么样」「谁和谁关系怎么样」，产出 ADD/UPDATE/DELETE，写进情感档案

两者各自清空自己的待合并缓冲，互不干扰。情感整理用独立 prompt，是为了不污染现在调好的事实 prompt。

## 衰减 & 遗忘

- **情绪**：`effective = intensity × 0.5^(age_days / half_life)`，`half_life = BASE × (1 + intensity)`（越强烈忘得越慢，对应 cogmem 半衰期）。
  `effective < MIN_INTENSITY` 或 `age_days > MAX_DAYS` → 自动遗忘。
- **关系**：不衰减，长期留，只靠新信息 UPDATE/DELETE 修正（跟事实一样）。

默认值（都进 .env 可调）：`BASE=3` 天、`MIN=0.15`、`MAX=30` 天。

## 注入

情感档案拼成第二段固定文本，**紧跟事实档案之后、上下文之前**注入：

> 【情感档案】以下是鲸鱼娘记住的、关于这个群近期情绪和人际关系的印象。
> 聊天时自然共情、关心（记得谁最近不开心、谁和谁关系好），但别逐条背出来；情绪会过时，太久没提的当没这回事：
> - 小明（情绪）：最近失恋心情低落
> - 小明↔小红（关系）：关系很好，常互怼

位置固定 → 事实档案那段的缓存收益不受影响。

## 错误处理 & 测试

- 情感合并失败 → 保留缓冲，下轮重试（跟现状一致）
- 衰减在**读取时**计算（`emotion_text` 顺带过滤过期项），不额外跑定时任务
- 单测：衰减函数（强度/天数 → 是否遗忘）；同人同情绪 UPDATE 不 ADD

## 配置项（.env）

```
EMO_HALF_LIFE_DAYS=3      # 情绪半衰期（天）
EMO_MIN_INTENSITY=0.15    # 衰减到低于此值即遗忘
EMO_MAX_DAYS=30           # 情绪条目最长保留天数（兜底）
EMO_MAX_CHARS=600         # 情感档案注入字数上限
```
